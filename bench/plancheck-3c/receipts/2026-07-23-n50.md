# plancheck-3c A/B receipts — 2026-07-23, n=50

**Question:** should defn flip `code(op:"read")` to default `mode:"summary"`
(via `DEFN_SUMMARY_READ_DEFAULT=1`)? #160 stage 3c decision.

**Verdict: NO** — keep `mode:"summary"` as opt-in per-call.

## Setup

- 50 tasks mined from recent git log via `mine-tasks.sh`; each task's
  objective is a commit subject, ground truth is the changed non-test
  Go files (1-4 per commit).
- Per task, two conditions: `off` (default body reads) and `on`
  (defn returns summary in place of body when available).
- Producer: `claude -p` subprocess with a temp `.mcp.json` toggling
  `DEFN_SUMMARY_READ_DEFAULT` per condition. Prompt asks for a fenced
  `ExecutionPlan` JSON block; harness parses it and hands to
  `plancheck check`.
- Recall = |ground_truth ∩ (filesToRead ∪ filesToModify ∪ filesToCreate)| / |ground_truth|.
- Ran serial (RAM discipline). Pilot at n=5 first, then remaining
  45 with `PLANCHECK_3C_OFFSET=5`. Cost-gated at $30 pilot / $60 rest.

## Per-task recall differences

Only 3 of 50 tasks had different recall between conditions:

| Task | off | on | Δ |
|---|---|---|---|
| 2d3cecd | 1.00 | 0.50 | -0.50 |
| 5bc1296 | 1.00 | 0.67 | -0.33 |
| f3c0089 | 0.33 | 0.67 | +0.33 |

Net: on lost 0.83 recall units across the 3, gained 0.33 → **net -0.50
recall for `on` across the 50-task set**. Trivial at aggregate, but a
consistent-direction miss on 2 tasks vs a single win.

## Why the mean lied

- Mean tokens for off was pulled by a 1.4M-token outlier task; median is
  identical to on.
- Mean wall for off was pulled by the 148.9s max; median is tied.
- The mean-based reading was "on is 18% fewer tokens, 9% faster." The
  median-based reading is "wash."

## Against the flip rule

README rule: **flip if recall drop <1pp AND wall/tokens improved ≥15%.**

- Recall drop: 0pp at aggregate mean, but 2 fewer perfect scores → marginal fail.
- Wall/tokens at median: essentially tied → **fails 15% threshold**.
- Wall/tokens at mean: hits 15% on tokens only; wall is 9%.

Two of three criteria are ambiguous or failing. Flipping the default
would trade a small always-on Haiku spend + slight recall regression for
tighter tail behavior. Not worth it.

## Followups worth considering

- The summary path's tail win is real (98s vs 148s worst-case).
  Could gate summary-mode on body-line count so it fires only when
  it would save the most — surface via defn's own preamble tip
  instead of a global default flip.
- Ground truth is git-log-derived; some off-by-one recall misses might
  be legitimate divergence (a plan that touches a related file which
  wasn't in the commit but is arguably part of the change). A future
  round could hand-audit the recall-0 rows to distinguish real misses
  from ground-truth artifacts.
