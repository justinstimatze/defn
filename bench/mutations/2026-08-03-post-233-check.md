## New finding: cache-write cost isn't in this report at all

`parseStreamJSON` (cmd/defn-bench/main.go) sums two usage fields per
assistant turn: `input_tokens` (fresh) and `cache_read_input_tokens`. It
never sums `cache_creation_input_tokens` — the field billed at a ~1.25x
premium when a turn *writes* a new cache segment rather than reading one.
Adjacent to, but distinct from, v3's already-documented "Cost, not tokens"
follow-up (which was about cache-read tokens inflating the *apparent*
"tokens used" total without hitting the wallet — a real cost concern this
report already correctly keeps out of the input/output columns). Cache
*writes* are a real dollar cost that's currently invisible everywhere in
this harness's output, in every past run, not just this one.

## Update: cache-creation accounting gap fixed same day

`CacheCreationTokens` now flows through `streamStats`/`mutationResult`/
`result` and is surfaced in every print/CSV site across `mutations.go`,
`chains.go`, `main.go`, `size_sweep.go`, and `your_repo.go` (labels
changed from `cache=` to `cacheR/cacheW=` throughout). A future bench
run against this fixture set will show the real cache-write cost that
was invisible above.

## Caveats

- n=1 per case — LLM agent runs are stochastic; no repeats to smooth
  variance (case 1's 11-call defn outlier is a good example of why that
  matters).
- Fixtures are all small (<20 lines) — v3 already flagged that defn's
  case for larger, wider-scope edits isn't exercised by this suite.
